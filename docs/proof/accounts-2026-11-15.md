- Implementation, Radar, Batcher: `forge verify-contract … --verifier blockscout` returned
  `Pass - Verified`; the Blockscout v2 API returns `is_verified: true` for all three.
- Factory: Blockscout classifies the factory as `proxy_type: basic_implementation` with
  implementation `0xC4f080498a720887b6086f13fBad5627d8abc470` (TroveAccount, verified), so its
  own v2 record reports `is_verified: false` and `forge verify-contract` reported
  "already verified" at deploy time. The factory is NOT a proxy functionally; this is Blockscout's
  proxy-detector misfiring on the ERC-1167 clone bytecode.
- Independent check: all four deployed runtime bytecodes MATCH the local `forge build`
  artifacts with immutable slots masked (TroveAccount 21,857 B / 66 slots, Factory 2,414 B /
  7 slots, Radar 3,726 B / 18 slots, Batcher 2,784 B / 0 slots). The factory's on-chain code
  is exactly the compiled TroveAccountFactory regardless of the Blockscout classification.
- Compiler: 0.8.24, optimizer 200, via_ir, evm_version paris — matching `contracts/foundry.toml`.
